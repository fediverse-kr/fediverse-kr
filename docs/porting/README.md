## 확정한 경계

- 서버 추천은 제외한다. 추천 점수·퀴즈·다양성 재정렬을 포팅하지 않는다. 일반 검색·필터·정렬은 유지한다.
- 첫 가입/로그인은 연합계정의 **새 공개 인증글**로 한다. 내부 회원 ID는 UUID이며 자체 ID/비밀번호는 로그인 뒤 원할 때 등록한다. ID/비밀번호만의 공개 회원가입은 없다.
- 한 회원에 여러 연합계정을 연결한다. 연결·소유 인증·공개 소개·사람 목록 노출은 별개다. 기본은 비공개.
- 연결한 계정이 없어도 자체 로그인은 가능하다. 180일/6개월 규칙은 회원가입에 복제하지 않는다. 등록/편집 등 행위 권한은 별도 정책으로 재검토한다.
- 기존 Phoenix UI는 가져오지 않는다. 랜딩/상세설명 데모 공통화는 별도 작업이며 이 계획의 백엔드와 분리한다.
- PostgreSQL을 유지한다. 개발용 별도 DB에만 새 `member_*` 테이블을 만든다. 원본 `users` 등을 덮어쓰거나 자동 매핑하지 않는다.

## 이번 작업에서 결정하지 않은 것

소개 페이지는 재기획 대상이다. 소프트웨어 종류·유저 직접 편집·디자인은 개선 대상이며, 운영/호스팅 사업자의 잘못된 정보를 위키식으로 고치는 권한·분쟁 정책은 미정이다. 크롤링·인증 포팅과 섞어 임의 확정하지 않는다. 실데이터는 import 리허설 때 필요하며 지금 구현의 선행 조건은 아니다.

## 1차 보안/제품 기준

- 자체 ID는 우선 영문 소문자·숫자·밑줄 3–32자(입력 대소문자 정규화), 표시 이름은 별도다. 비밀번호는 공백을 포함해 입력 그대로 해시하며 15–128자와 바이트 상한을 둔다.
- Argon2id + 개별 무작위 salt. 비밀번호와 원문 세션 토큰은 로그/SSR/응답 JSON에 포함하지 않는다. 세션은 HttpOnly, SameSite=Lax, HTTPS에서는 Secure 쿠키이며 DB에는 토큰 해시만 저장한다.
- 서버 설정의 단일 origin을 기준으로 변경 요청을 검증한다. Host/X-Forwarded-Host를 신뢰해 origin을 만들지 않는다. 로그인 CSRF도 검사한다. 사용자 식별/세션 상태 응답은 no-store.
- 가입·로그인/비밀번호 검증에 시도 제한과 비싼 해시 작업 동시성 제한을 둔다. 비밀번호 변경에는 현재 비밀번호가 필요하며 기존 세션을 폐기한다.
- 연합계정 연동은 **새 공개 게시글을 강제**한다. OAuth/MiAuth 또는 프로필 편집 인증으로 전환하지 않는다. 공개 인증글과 연결 계정 목록의 공개 여부는 구분한다. 외부 서버에 실제 글을 쓰거나 앱을 등록하지 않았다.
- 기존 연결 계정의 새 공개 인증글 재인증으로 암호를 복구한다. 새 계정 연결만으로는 복구 권한을 얻지 않는다. 이메일 수집·회원 병합·모든 로그인 수단을 잃은 경우의 복구·6개월 계산 기준은 별도 항목이다. 연동 공개 설정은 저장하되 공개 프로필/목록 완성과는 구분한다.
- 기존 DB 직접 연결/마이그레이션/실제 회원 이전·외부 계정 변경은 이번 요청의 개발 착수와 구분한다.

## 근거와 실행

- [OWASP 비밀번호 저장](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html): Argon2id 기준.
- [Dioxus 0.7 서버 함수](https://dioxuslabs.com/learn/0.7/essentials/fullstack/server_functions/): typed API와 서버 전용 요청 추출.
- Diesel/diesel-async + bb8: PostgreSQL 저장소. Diesel embedded migrations: 실행 바이너리에 포함.
- `.env.example`: 필요한 설정 이름. 파일은 자동 로드하지 않으며 실제 비밀번호/접속 정보를 저장소에 넣지 않는다.
- DB가 설정된 서버는 시작 시 내장 마이그레이션과 지속 서명키를 준비한다. 선택형 개발 명령은 같은 바이너리의 `cargo run --no-default-features --features server --bin fediversekr2 -- --migrate`다. 별도 worker/migration 컨테이너는 없다.

## 실행과 남은 경계

`./scripts/dev.ps1 -Mode Setup`으로 최초 개발 클러스터·DB·스키마·지속 서명키를 준비하고, `./scripts/dev.ps1`로 SSR 개발 서버를 띄운다. `-Mode Test`는 실제 DB 테스트를 포함한다. 시스템 PostgreSQL 서비스/운영 DB는 사용하지 않는다.

- `.local/postgres`, loopback `127.0.0.1:16439`, `fedkr_dev` / `fedkr_test`만 개발 마이그레이션 대상이다. 로컬 trust 인증은 **개발 전용**이며 다른 로컬 프로세스는 접근할 수 있다. 외부 공개 금지.
- `FEDKR_PUBLIC_ORIGIN`은 정확한 origin이며 HTTPS 필수(개발용 literal loopback HTTP만 예외). `.env.example`는 자동 로드하지 않는다.
- `/actor`는 지속 저장된 RSA 키의 **공개키** 발견용이다. inbox·배달 기능은 없다. 원격 서버가 공개키를 조회할 수 있는 HTTPS 환경 전에는 authorized-fetch 실서버 호환 완료가 아니다.
- AP 읽기부터 모듈화했다. 기존 Phoenix의 제품별 REST fallback·이사/alias까지 모두 포팅한 것은 아니다.
- 새 인증글은 30분 유효, 선택형 자격증명 등록은 15분 이내 세션 필요. 암호 변경은 현재 암호 확인 후 기존 세션을 전부 폐기한다.
- 브라우저/ID/회원별 제한, 전체 인증 시도 제한과 해싱/네트워크 동시성 상한을 적용했다. 배포 시 프록시 신뢰 경계·IP별 제한을 추가 검증해야 한다.
- 연결 해제·공개 설정 저장·기존 AP 재인증 복구·탈퇴·구 회원 첫 로그인은 연결했다. 구 이미지 삭제·공개 프로필/목록·실데이터 이관·활성화·배포는 미완료다.

테스트 증거는 `integration-checks.md`, 실제 의존성 라이선스 범위는 `dependency-licenses.md`를 참조한다.
