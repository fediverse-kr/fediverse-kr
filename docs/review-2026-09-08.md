# Reviewable experience draft — 2026-09-08

## Design decision

One central proposition: keep the space and account you chose while communicating with people elsewhere. Home demonstrates this through composing a greeting and receiving a reply. One additional BookWyrm → Mastodon example shows different software; the broader activity catalogue stays on `/platforms`. The design is not a promise of universal feature compatibility.

## Verification

- Dioxus fullstack development build successful; latest build includes a static trusted textarea default to avoid raw-text SSR hydration markers. User content never enters raw HTML.
- Five unit tests passed: server search/filter behavior and bounded story durations.
- Five public routes returned HTTP 200 with server-rendered headings and unhydrated initial state.
- Browser checklist: 37 assertions passed at 1440px and 390px; an additional 320px width check passed.
- Default initial and complete conversations fit their internal viewport: 357px desktop, 361px mobile. Both reply slots remain 180px throughout; no cue collapse/re-expand.
- Pause freezes progression; replay cancels the current story; empty greetings cannot submit. Mobile does not automatically switch away from the user's home.
- The same posted greeting appears on both servers. A separate fresh-context check delivered a custom greeting twice, observed no HTTP 4xx/5xx or page errors, and confirmed `prefers-reduced-motion` makes the reply animation `none`.
- JavaScript-disabled check: textarea value is exactly `안녕하세요 처음이에요`, without internal hydration markers. Interactive controls remain disabled until hydration.
- All six activity tabs, book-review presentation switch, event details and imagery load were checked.
- Three generated image sources have embedded prompt metadata. Build output is a 117KB scene JPEG and two approximately 3KB avatar JPEGs.
- Phoenix reference worktree remained clean.

## Independent review

Disposition: **ship as a reviewable prototype**. Reviewer inspected eight settled desktop/mobile images and current source, and found no material visual or interaction blocker. A nonblocking missing space at the mobile hero line join was corrected.

The automated detector flagged a thick edge on the depicted book spine, which the reviewer accepted as a physical book detail rather than a navigation-card accent. New values outside the previous design-system document were advisory findings, not evidence of a clean detector result.

## Limits

No real federation, posting, account, DB, crawler, joining, event registration, video playback, or live directory is implemented. No production release build or newcomer comprehension study was performed. Images of settled states do not establish animation or assistive-technology behavior; timing and reduced-motion checks above are separate browser observations. Full keyboard/screen-reader acceptance remains unverified.
