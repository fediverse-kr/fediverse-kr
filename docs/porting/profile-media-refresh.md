# 회원 사진·커스텀 이모지 갱신 — 2026-09-14

Phoenix MIT reference의 `AuthController.find_or_create_user/2`,
`Accounts.refetch_user_profile/1`, `ActivityPub`의 icon/Emoji tag 해석,
`AvatarFetcher`를 대조했다. 기존 앱은 로그인 때 이미지를 저장했으나 신버전은
이관 파일 조회만 하던 공백을 연결한다. 공개 인증글 방식은 변경하지 않는다.

## 실제 흐름

- 공개 AP 인증 성공 뒤 해당 계정의 사진·이모지를 같은 서버 프로세스에서 가져온다.
  이미지 실패 때문에 성공한 로그인을 취소하지 않는다.
- `/account`의 ‘사진과 이모지’에서 연동한 계정을 골라 다시 가져올 수 있다.
  이미 선택한 출처가 있다면 다른 연동 계정의 로그인/재인증으로 자동 교체하지 않는다.
- fediverse.kr의 표시 이름, 연동 공개 여부는 갱신하지 않는다. 이미지는 계속 본인에게만
  `/api/member/avatar`, `/api/member/emoji/:name`으로 제공한다. 외부 이미지 URL을 브라우저에 넘기지 않는다.
- 진행 상태를 표시하고 자동 갱신이 끝나면 화면의 이미지도 다시 읽는다. 실패 안내는 DB에 남고,
  프로세스 중단으로 미완료 개인 요청이 남으면 2분 후 실패 상태로 표시한다. 개인 요청의 자동 재시도는
  추가하지 않았다. 다음 로그인/수동 가져오기로 재시도하며 회원별 요청 간격은 1분이다.
- 해당 출처 계정 연결 해제 시 runtime 사진·이모지를 비우고 기존 해제 절차대로 세션을 폐기한다.
  탈퇴 시 새 이미지도 기존 PG/OpenDAL 정리 경로를 따른다.

## 경계와 보존

- 새 내장 migration `202609140022_profile_media`. runtime 상태는 `member_profile_media`에 저장하고
  원본 Phoenix projection/파일 inventory를 수정하지 않는다. runtime 행이 없을 때만 legacy 이미지를
  사용한다. runtime에서 제거한 사진을 legacy fallback으로 다시 표시하지 않는다.
- 수동 갱신은 DB에 귀속된 handle로 WebFinger/AP를 다시 조회하고 고정된 actor ID와 비교한다.
  URL의 소유자가 바뀌면 거절한다. 클라이언트가 제공한 이미지 URL이나 표시 이름은 사용하지 않는다.
- 아바타 1 MiB, 이모지 각 256 KiB·최대 10개는 Phoenix와 같은 상한이다.
  기존 crawler의 reqwest/DNS 고정/HTTPS/redirect 재검사/10초·응답 크기 제한을 재사용한다.
  전체 갱신 동시 2개, 각 갱신의 다운로드 동시 4개, 디코더 동시 2개다.
- `image`의 PNG/JPEG/WebP/GIF 첫 프레임 디코딩과 픽셀/할당 상한을 로고와 공통화했다.
  AP 이미지의 애니메이션은 허용하되 전체 프레임 검증이라고 주장하지 않는다. 로고는 계속 정지
  PNG/JPEG/WebP만 허용한다. SVG는 기존 XML 검사와 분리된 sandbox 이미지 응답을 사용하며
  HTML 삽입/정화 도구로 취급하지 않는다. 바이트를 변환하거나 재인코딩하지 않는다.
- 특정 이미지 다운로드 실패 시 이전 사진/동명 이모지는 보존한다. 정상 AP 응답에서 아예
  사라진 icon/tag는 제거로 취급한다. 없는 새 이모지의 실패는 텍스트 shortcode로 남는다.
- 파일 저장은 로고와 같은 OpenDAL publication, OS 저장소 잠금 → 회원/세션 → PG 매핑 잠금 순서다.
  저장 전 orphan 정리 예약, 저장 후 연결·세션·요청 번호 재검사를 포함한 DB commit을 사용한다.
  재요청/로그아웃/차단/연결 해제 뒤 늦게 도착한 결과는 반영하지 않는다.
- 이미 사용 중인 runtime 프로필이 있는 격리 사본은 재이관으로 초기화하지 않는다.

## 관리자 전체 갱신

Phoenix `AdminLive`의 `refetch_all_profiles`를 `/account/moderation/profiles`에 연결했다.
새 프로필 편집기나 별도 다운로드기를 만들지 않고 위 AP·OpenDAL 경로를 공유한다.

- 기존 관리자 메뉴에서 확인란 → 시작 → 건수/진행 막대 → 남은 작업 중단.
  시작에는 현재 관리자 권한과 15분 이내 인증이 필요하다. 읽기/중단도 관리자 전용이다.
- 내장 migration `202609140023_profile_batches`의 두 PG 테이블에 대상과 진행을 저장한다.
  동시에 한 묶음만 실행하며 중복 시작은 같은 작업을 반환한다. 시작 이후 가입자는 추가하지 않는다.
- 웹과 같은 바이너리의 워커가 처리한다. 로그인 후 개인 갱신과 동일한 두 개의 동시 실행 한도를
  사용하고, 새 컨테이너·브로커·라이브러리는 없다. 3분 임대가 만료된 중단 작업은 최대 3회 회수한다.
  일반 원격 실패는 실패로 기록하고 다음 전체 갱신에서 재시도한다.
- 로그아웃/창 닫기는 명시적으로 시작한 전체 작업을 취소하지 않는다. 저장 시마다 작업/임대,
  현재 관리자 권한·ban·존재 여부, 대상 회원·연동·선택 출처·요청 번호를 다시 확인한다.
  중단·권한 회수·탈퇴·연결 해제 후 유효하지 않은 결과는 반영하지 않는다.
- 회원이 정한 출처를 유지한다. 아직 선택하지 않았고 연동이 하나뿐이면 그 계정을 쓰며,
  여러 계정 중 임의 선택하거나 연결 해제한 출처를 되살리지 않는다. 최근 1분 내 갱신은 건너뛴다.
- 아직 신버전에서 인증하지 않은 Phoenix 회원은 보존된 handle로 **이미지만** 갱신한다.
  actor 고정, 계정 연동, 회원 인증을 수행하지 않는다. 해당 회원이 그 사이 인증하면 옛 결과를 거절한다.
- 진행 응답은 건수와 묶음 ID만 제공한다. 회원별 주소·이미지 키·원격 오류 원문은 공개하지 않는다.
  기존 파일 보존과 재이관 거부 규칙에도 새 테이블을 포함한다.

## 검증 범위

- `db::profile_refresh::tests`: 실제 격리 PG/OpenDAL 저장·읽기·교체, 부분 실패,
  legacy fallback/제거/탈퇴, 비공개·이름 보존, 연결 해제, 경합·세션/ban 재검사.
- AP parser와 기존 공개 인증 verifier 검사에서 canonical actor의 이미지 정보를 함께 확인한다.
- `scripts/check-profile-media-browser.js`: 실제 HTTP 거절/갱신 실패·기존 이미지 보존,
  사용자 안내·1440/390/320px·실제 이미지 디코딩. 성공 AP 응답을 가로채서 만들지 않는다.
- `db::profile_refresh::tests::batches`: 실제 격리 PG/OpenDAL에서 관리자/최근 인증, 대상 고정,
  선택 출처/legacy 비인증, 취소·권한 회수·연결 해제·탈퇴·임대 재획득·늦은 결과 거절을 검사한다.
- `check-profile-batch-browser.js`: 실제 관리자 메뉴·시작·진행·완료·중단·재로드·모바일,
  동일 프로세스 워커의 실패 처리와 원래 이미지/개인 설정 보존. 성공 AP 응답 모킹은 하지 않는다.
- 양 플랫폼 release 수명주기 검사에 재시작 후 만료된 프로필 작업을 실제 바이너리가 회수하는
  검사를 추가했다. 외부 AP 성공 상호운용과 실제 회원 백업 복원/운영 전환은 여전히 별도다.

실행별 결과는 [integration-checks.md](integration-checks.md)를 따른다.
