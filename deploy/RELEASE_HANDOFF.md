# 배포 인계 — 새 소개 릴리즈

상태: **실제 DB 복원·이관·재대조 통과. PEM 호환 수정 후 Linux/OCI 후보 재생성 필요.**
기존 ZIP/OCI에는 이번 수정이 없어 그대로 배포하지 않는다. 상세 결과는
[실자료 리허설](../docs/porting/real-data-rehearsal.md)의 현재 결과를 따른다.
아래 실자료 이관·인증·파일·운영 조건을 확인하기 전에는 Phoenix를 내리거나 트래픽을 전환하지 않는다.
운영 실행자는 배포를 승인받은 유지보수자다. 로컬 구현 완료와 실제 배포 완료는 다르다.

## 전달할 릴리즈 묶음

- 고정된 소스 revision, Cargo.lock과 대응하는 Linux 서버/웹 자산.
- 서버·자산을 함께 담은 컨테이너 이미지의 불변 digest, 배포 고지.
- 아래 환경 입력, 실제 사본 검증 결과, 남은 확인 사항과 전환/복귀 기록.

아래 기존 후보의 앱 입력: `e0a543fb55b786a3ccc5523616cbf278d73a8938`.
이후 실제 이관에서 발견한 PEM 호환 수정이 소스 세 파일에 추가되어 기존 후보를 대체해야 한다.
전달 묶음의 `RELEASE.txt`에 최종 소스 revision, `SHA256SUMS`에 파일 무결성을 기록한다.
과거 로컬 v15 이미지를 최신 후보로 간주하지 않는다.
기존 배포 검증 대상은 linux/amd64였다. 운영 노드 아키텍처를 확인한 뒤 같은 대상으로 최종 검증한다.
구체적인 이미지 전달/레지스트리 경로는 운영 입력을 받은 뒤 확정한다. 개인 경로나 실자료를 이미지에 담지 않는다.

### 이번에 전달하는 파일

묶음은 로컬 전달 디렉터리에 보관한다. 기존 Windows checkout은 보존본이며 현재 원본은
`<workspace>/fediversekr2`다. 자세한 재현/검증 범위는 [최종 후보 기록](../docs/porting/final-release-candidate.md)을 따른다.

- `fediversekr2-linux-amd64.oci.tar`: 검증한 이미지, 44,477,952 bytes.
- `fediversekr2-source.tar.gz`: 대응하는 소스/lock/배포 도구/인계 문서. 실자료와 캐시는 제외.
- `RELEASE.txt`, `SHA256SUMS`: revision과 배포물 구분, 파일 해시.

이미지 ID는 `a092c1cdc6407d56118d9f48ce75f2d98c30d1224e1e4ce99e52078134d6e547`,
OCI manifest digest는 `sha256:7382231921f59eb060c68a3d9c37c11774bcad99ca3ac310a5d18992207b14db`다.
레지스트리 게시 digest는 아직 없으며, 올린 뒤 실제 digest를 다시 기록한다.
OCI archive SHA-256은 `25de1a8ccbdb304685ef3d996677616a5f7fd0832447a553a59e3794a30499fa`다.

최종 Linux/OCI 검사는 합성 자료로 219개 통과했다. DB 중단/복구와 worker monitor 검사는
원시 Linux ELF 경로에 포함되었다. 이 결과로 실회원 인증·행 이관·운영 볼륨 권한을 대체하지 않는다.
실제 Linux preview 서버의 PC/모바일 hydration, 입문 페이지 이동과 스크롤도 별도 통과했다.

## 운영 실행에 필요한 환경 정보

비밀값 자체를 응답/문서에 쓰지 말고, 준비 여부와 안전한 전달 방법만 알린다.

| 항목 | 필요한 확인 |
| --- | --- |
| 실행 대상 | 노드 아키텍처, namespace/기존 배치, 가용 CPU/RAM/디스크 |
| PostgreSQL | 서비스 주소, DB 버전, CA/TLS, DB·역할 준비/백업·복구 방법 |
| 파일 저장소 | 실제 아바타·이모지·파비콘·제품 로고 export, 영속 볼륨과 UID/GID 권한 |
| 공개 주소 | fediverse.kr HTTPS/프록시, `/actor` 공개키 발견, 상태 확인 경로 |
| 이관 자료 | 암호화 백업의 안전한 복호화, 최신 DB와 파일 사본의 기준 시각 |
| 계정/운영 | 기존 회원 인증 확인에 참여할 계정, 관리자 지정, 전환 유지보수 창 |

기본 실행 구성은 앱 HTTP+워커 한 프로세스와 PG다. 이번 릴리즈는 현재 PG 큐를 유지하며
NATS/Kameo 또는 별도 워커 컨테이너를 추가하지 않는다.

### 받은 백업의 현재 확인 상태

- 사용자가 전달한 기존 로컬 ZIP의 해제와 파일 무결성 검사가 성공했다. 새 다운로드는 하지 않았다.
- DB 덤프·스키마·복원 안내·체크섬 등 6개 파일이다. 암호는 기록하지 않는다.
- 작성자 설명상 2026-09-13 12:43 KST의 PG 16.15 원본 사본이며, 작성자가 12개 테이블 복원을 확인했다.
  작성자 체크섬 5개 항목도 로컬에서 통과했다.
- 사용자 승인 방식 변경 후 로컬 PG 17에 실제 복원하여 12개 테이블의 집계와 외래키 8개를
  대조했다. 수정된 CLI의 dry-run/apply/repeat는 모두 통과했고 데이터는 격리 상태다.
  회원 10명, 서버 97개, 수집 이력 138,235건, 서명키 1개 및 나머지 business table을 검증했다.
  UUID/차단 상태/키 원문을 보존했고 작업 큐·세션·activation은 비어 있다. PG는 종료·보존했다.
  새 후보와 실제 운영 조건에서도 아래 전환 리허설을 수행해야 한다.
- **DB 외부 S3 이미지·파일은 이 ZIP에 포함되지 않았다.** 유지보수자는 해당 snapshot에 대응하는
  아바타·이모지·파비콘·제품 로고의 파일 export를 별도로 준비해야 한다. DB 키만으로 활성화하지 않는다.
  로컬 importer가 확인한 외부 파일 참조는 112건이다(고유 파일 수가 아님).

## 실자료 리허설 순서

이미 있는 명령과 도구를 사용한다. 빈 합성 DB 검사를 실자료 검증으로 기록하지 않는다.

1. 원본 DB/파일 백업은 그대로 보존하고 비공개 격리 PostgreSQL에 사본을 복원한다.
   개발용 trust DB에는 실회원 정보를 넣지 않는다. 덤프는 PostgreSQL 기본 복원 도구를 사용한다.
2. [기존 이관 명령](../docs/porting/legacy-import.md)의 source/target 규칙으로 검사 후 적용한다.
   `--legacy-import`, 이어 `--legacy-import --apply`.
3. [기존 파일 보존](../docs/porting/legacy-assets.md)을 검사 후 적용한다.
   `--legacy-assets`, 이어 `--legacy-assets --apply`. 이미지 키뿐 아니라 실제 바이트가 필요하다.
4. 사용자 ID·계정 귀속·오너·차단·댓글·숨김·카탈로그·서명키·파일을 원본과 대조한다.
   예외/누락은 건수와 분류만 전달하고 실회원 행·주소·키는 출력하지 않는다.
5. 검토한 대상 사본만 정해진 live 이름으로 바꾸고 [활성화](../docs/porting/activation.md)를 수행한다.
   `--legacy-activate`, 검토와 조건 확인 뒤에만 `--legacy-activate --apply`.
6. 실제 공개 origin에 맞춘 후보에서 HTTPS/AP·기존 회원 로그인·권한·조회·이미지·워커를 확인한다.
   사용자 인증글 게시와 실제 계정 조작은 해당 계정 주인의 동의 아래 수행한다.

위 명령은 동일 배포 바이너리의 오프라인 모드다. HTTP/워커를 동시에 실행하는 명령이 아니다.
import/activation은 현재 literal loopback의 정해진 DB명을 요구한다. 이관 실행 환경을 그 계약에
맞추고, 편의를 위해 검증/격리 표식을 삭제하거나 원본 DB에 실행하지 않는다.
접속 문자열과 암호는 제한된 프로세스 환경으로 공급하며 문서/명령행 인수/대화에 기록하지 않는다.

## 실제 운영 실행 계약

- `FEDKR_DATABASE_URL`: 활성화한 대상 DB. 앱 시작 시 내장 migration과 활성화 상태를 확인한다.
- `FEDKR_PUBLIC_ORIGIN`: 활성화 승인과 동일한 정규화 HTTPS origin.
- `FEDKR_DATABASE_CA_FILE`: 사설 CA가 필요한 경우만 읽기 전용 인증서 파일.
- `FEDKR_MEDIA_DIR`: 검증한 live 파일 묶음. 원본 백업이 아닌 별도 영속 사본이며 읽기/쓰기/삭제 권한 필요.
- 이미지를 root로 실행해 권한 문제를 우회하지 않는다. 서버와 matching `public/`는 같은 빌드에서 가져온다.
- `/healthz`는 HTTP 생존, `/readyz`는 기동/DB 확인이다. 성공 응답만으로 실자료/AP 검증 통과로 처리하지 않는다.
- 정상 종료 유예는 기존 [컨테이너 계약](container/README.md)을 따른다. 강제 종료 후 작업 회수도 확인한다.

## 전환과 복귀

1. 사용자에게 유지보수 시작을 알리고 Phoenix 쓰기를 중지한다.
2. 최종 DB/파일 사본으로 같은 이관·대조 절차를 반복한다. 오래된 리허설 DB를 그대로 운영에 올리지 않는다.
3. 후보의 비공개 점검을 통과한 뒤 트래픽을 전환한다. 동시에 서로 다른 DB로 쓰는 두 서비스를 열지 않는다.
4. 공개 주소에서 랜딩→입문→서버 찾기, 로그인, 이미지, 수집을 점검한 뒤 완료를 보고한다.
5. 복귀가 필요하면 새 서비스의 쓰기를 먼저 중지하고 전환 후 변경을 보존한다.
   새 쓰기가 생겼다면 이미지 태그만 되돌리는 것을 데이터 복구라고 하지 않는다.
   원본 복구와 새 쓰기 반영 범위는 운영자와 확인하며, 자동 역이관이 구현되어 있다고 가정하지 않는다.

## 돌려받을 완료 결과

비밀 없는 결과만 회신한다: 배포 revision/digest, 전환 시각, 원본/대상 대조의 성공 여부와
누락 건수, 공개 URL 확인, 기존 회원 로그인/권한, 이미지, 수집/재시작, 복귀 수단 보존 여부.
실패·생략 항목은 명시한다. 이 결과를 확인하기 전까지 새 목표를 실제 배포 완료로 처리하지 않는다.
