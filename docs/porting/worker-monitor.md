# 관리자 수집 현황

`/account/moderation/workers`에서 정기 수집의 최근 기록을 확인한다.
기존 Phoenix의 운영 기능 이식이 아니라 수집 실패를 확인하기 위한 보완이다.
새 워커, 재시도 엔진, DB 마이그레이션이나 의존성을 추가하지 않는다.

## 접근과 갱신

화면은 기존 `AdminNav`와 관리자 레이아웃을 사용한다. API
`/api/member/moderation/workers`는 현재 세션과 관리자 권한을 확인하므로
관리자 전용 읽기 요청이다. 세션이 없거나 권한이 없으면 화면에는 공통
오류 안내가 표시된다.

서버에서 `use_server_future`로 첫 스냅샷을 SSR하고, hydration이 준비된
브라우저에서 성공적으로 읽은 경우에만 15초마다 다시 조회한다. 사용자는
수동 새로고침도 할 수 있다. 로딩 중에는 새로고침을 비활성화하며, 실패한
요청은 다시 인증하거나 새로고침할 수 있다.

## 표시 의미

작업 요약의 큐 수는 조회 시점의 `directory_jobs` 상태를 분류한 값이다.

| 항목 | 의미 |
| --- | --- |
| 실행 대기 / 예약 | 실행 가능한 pending 작업과 아직 예정 시간이 되지 않은 작업 |
| 종료 서버 보류 | 종료된 서버의 owner 요청이 아닌 pending 작업 |
| 실행 중 | 아직 임대 기한이 남은 running 작업 |
| 회수 대기 | 임대가 없거나 만료된 running 작업 |
| 중단 | `dead` 작업 |
| 최근 24시간 완료 | 최근 24시간 안에 `complete` 상태가 된 작업 |

`완료`는 작업 레코드가 `complete`가 되었다는 뜻이며, 상대 서버가 원격
조회에 성공했다는 보장은 아니다. 마지막 완료 시각과 조회 시각도 같은
DB 스냅샷의 시각 정보다. 이 화면은 worker heartbeat가 아니므로 전체
시스템의 정상 또는 비정상을 단정하지 않는다.

## 두 종류의 확인 필요 항목

작업 이슈와 상대 서버 이슈를 섞지 않는다.

- 작업 이슈는 임대 회수 대기(`LeaseExpired`)와 중단(`Dead`)이다. 자동
  시도는 최대 3회이며 중단 기록은 이후 정기 수집이 성공해도 남는다.
  종료하지 않은 서버는 다음 정기 수집 대상이고, 개별 재수집은 기존
  서버 관리에서 요청한다. 종료 서버는 자동 수집 대상으로 바꾸지 않는다.
- 상대 서버 이슈는 최신 observation에서 상대 서버 응답이 없거나
  NodeInfo 확인이 실패한 경우다. 외부 사이트 실패는 워커 장애를 뜻하지
  않는다.

각 영역은 전체 건수와 최근 최대 20건을 표시한다. 사이트 이슈 조회에는
숨김 서버를 제외하는 조건이 없으므로 숨김 서버도 포함되지만, 종료된
서버(`is_closed`)는 상대 서버 이슈에서 제외된다. 확인할 항목의
`서버 관리에서 확인` 링크는 기존 `/account/moderation/sites/:id` 관리
화면으로 이동하며 이 화면에 재실행 버튼은 없다.

API DTO에는 도메인, 상태, 시도 횟수, 시각과 안전한 상태 코드만 포함한다.
원시 worker 오류, lease token, 인증정보, 회원 프로필 데이터는 화면이나
응답에 노출하지 않는다.

## 검증 상태

현재 문서는 구현 계약과 표시 의미를 기록한 것이다. 이 시점에는 Cargo
빌드, PostgreSQL 운영 검증, 실제 브라우저 검증을 완료했다고 주장하지
않는다.
