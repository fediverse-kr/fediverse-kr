# 기존 회원의 첫 로그인 연결

2026-09-14. 합성 Phoenix 데이터와 실제 격리 PostgreSQL에서 구현·검증한다.
운영 ZIP을 열거나, 원격 SNS에 인증글을 게시하거나, 이관 DB를 운영으로 활성화하지 않았다.

## 기준은 Phoenix의 기존 로그인

MIT 참조 코드의 `lib/fediverse_kr/accounts/accounts.ex`에 있는
`get_user_by_handle/1`은 공백·앞쪽 @·대소문자를 정규화해 기존 회원을 찾는다.
`lib/fediverse_kr_web/controllers/auth_controller.ex`의 `check_verification/2` →
`find_or_create_user/2`는 인증 성공 뒤 그 회원을 재사용한다. 기존 `User`에는
불변 AP actor ID가 없고 계정 주소가 있다. 새 가입일·새 UUID를 만들어 기존 권한과
분리하는 방식이 아니었다.

신버전도 **현재 계정의 새 공개 인증글**을 검증한 뒤 같은 회원 UUID로 로그인한다.
주소 문자열만 제출하거나 이전 DB에 주소가 있다는 이유로 로그인시키지 않는다.
옛 인증코드·세션도 재사용하지 않는다. 프로필 코드 인증, OAuth, 6개월 조건은 추가하지 않는다.

## 연결과 보존

1. 기존 importer가 같은 UUID의 회원 및 정규화된 비공개 주소 예약을 만든다.
2. 기존 주소로 WebFinger/AP 계정 조회와 새 공개 인증글 검증을 수행한다.
3. 같은 트랜잭션에서 회원의 차단 상태·현재 연결·challenge를 다시 검사한다.
4. 이전 UUID에 AP actor ID를 최초 고정하고, 비공개 연동과 새 세션을 만든다.

따라서 댓글 작성자, 신고 관계, 서버 소유권, 기존 표시 이름·가입 시각을 유지한다.
사용자가 선택형 자체 ID/Argon2id 암호를 나중에 등록하는 흐름도 같다.
긴 표시 이름의 UI용 축약과 원문 보존은 importer 계약을 유지한다.

## 최초 귀속의 신뢰 한계

이전 DB에는 과거 actor ID가 없으므로, **첫 귀속 전 주소가 재사용됐는지 과거 DB만으로
증명할 수는 없다.** 처음 한 번은 기존 Phoenix와 마찬가지로 현재 원격 서버가
증명하는 주소 소유권에 의존한다. 원격 운영자가 계정/글을 조작할 수 있다는 경계도 같다.
이를 과거부터 불변 actor가 검증된 것처럼 표현하지 않는다.

첫 귀속 이후에는 실제 검증한 actor ID를 저장한다. 같은 주소의 다른 actor가 옛 권한을
가져가거나 기존 고정을 덮을 수 없다. 같은 actor의 주소 변경은 허용하지만 다른 옛 회원의
예약 주소와 겹치면 병합하지 않고 거절한다. 실제 이전 데이터의 주소 충돌과 인증 가능한
원격 서버는 전환 리허설에서 별도로 확인해야 한다.

## 수명과 경합

- 다른 회원으로 로그인한 상태에서 옛 예약 계정을 추가해 그 회원의 권한을 합칠 수 없다.
- 서로 다른 actor가 같은 옛 주소를 동시에 증명해도 한 연결만 성공한다.
- 회원 잠금 후 예약·연결을 다시 확인한다. 연결 해제/탈퇴 전에 읽은 오래된 권한으로
  뒤늦게 연결을 복원할 수 없다. 실패하면 연결·고정·challenge 소비·세션 전체가 롤백된다.
- 연결 해제 후에도 actor 고정은 남는다. 해제한 계정은 익명 복구 수단이 아니다.
  남은 로그인 수단으로 최근 인증한 본인만 재연결할 수 있으며, 재연결만으로 기존 회원의
  연합 재인증 시각을 갱신하지 않는다.
- 탈퇴는 예약도 삭제한다. 새 가입은 새 UUID이며 옛 댓글/서버 권한을 되살리지 않는다.
- ban 상태는 첫 귀속 전후 모두 로그인 거절 대상으로 유지된다.

## 저장과 이관 안전

내장 migration `202609140011_legacy_identity`가 예약 테이블에 nullable
`actor_url` UNIQUE와 `claimed_at`을 추가한다. 둘은 함께 비어 있거나 함께 채워져야 한다.
기존 migration을 수정하지 않았다. 고정된 계정이 있으면 역 migration은 거절한다.

이미 고정된 주소는 재이관 검사의 미사용 예약과 다르다. 다른 새 상태가 하나도 없어도
재이관이 이를 초기화하지 않고 거절한다. importer quarantine과 웹/워커 시작 거절은 그대로다.
**이 로그인 구현은 격리 해제·운영 승격 기능이 아니다.**

## 검증 범위

- `backend::db::members::legacy::tests`: 이전 UUID·댓글·오너 보존, 기본 비공개,
  대소문자 정규화, 재로그인/재사용 거절, 잘못된 proof, ban, 다른 회원 세션,
  동시 최초 귀속, 해제 후 로그인·암호 복구 경계, 주소 변경·병합 거절, 탈퇴.
- `backend::db::legacy::tests`: 실제 합성 Phoenix import → 공개 AP proof → 이전 UUID와
  오너 접근, 원본 이름/비공개 신고/댓글 보존, 원본 불변, quarantine 유지,
  고정만 있는 경우도 재이관 거절.
- verifier에는 가상 AP 문서를 공급한다. 실제 DB 트랜잭션을 사용하되 공개 인증 우회 API는 없다.
- 실행 결과와 빌드 범위는 [통합 검증 기록](integration-checks.md), 전체 미완료는
  [교체 준비 현황](../cutover-readiness.md)을 기준으로 한다.
