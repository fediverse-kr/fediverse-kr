## 검토 경로

| 경로 | 동작 |
| --- | --- |
| /platforms | 종류에서 출발, 등록 링크 노출 |
| /software/:name | 공개 소개, 정보 수정·변경 이력 진입 |
| /account/software/new | 새 식별자와 소개 등록 |
| /account/software/:name/edit | 기존 소개 직접 수정 (식별자 new도 등록 경로와 충돌하지 않음) |
| /software/:name/history | 공개 변경 이력, 버전별 내용 보기 |
| /account/software/:name/restore/:revision | 현재/이전 내용 비교 후 명시적으로 복원 |

DB 미설정 미리보기에서는 입력을 시험할 수 있지만 저장 버튼은 비활성이다. 실제 DB 장애를 예시로 감추지 않는다. 읽기는 SSR, 쓰기는 로그인·Origin 검증이 있는 POST다. 개인 계정 조회는 /account 아래에서만 하며 이 경로의 응답은 private, no-store다. 공개 이력에는 회원 세션을 직렬화하지 않는다.

## 편집 계약

- 편집 가능: 표시 이름, 계열, 소개, 기존 종류 선택, 기능, 프로젝트 웹사이트, 사용 기술.
- 식별자는 등록 때 소문자로 정규화한다. ASCII 영문·숫자·하이픈·밑줄 64바이트 이하, 첫 글자는 영문/숫자. 기존 식별자는 임의로 바꾸지 않는다.
- 수정에서 logo_key, brand_color, is_featured, display_order, 내부 ID를 받지 않는다. 복원도 이 필드를 되돌리지 않는다.
- 문자열은 HTML이 아닌 일반 텍스트이며 UI에서 이스케이프된다. 웹사이트는 http/https, 자격 증명 없는 주소만 허용. 저장 시 원격 요청하지 않는다.
- 표시 이름 200자, 계열 128자, 소개 4,000자, 기능 32개×300자, 기술 1,000자, 웹사이트 2,048자, 변경 요약 200자. 종류는 1~32개. 쓰기 요청 본문은 이 두 경로에만 64KiB, 복원은 8KiB다.
- 종류는 카탈로그의 기존 항목을 고른다. 기존 소프트웨어에 남아 있는 미등록 분류는 유지 가능하지만 새로 주입할 수 없다. 선택지 조회는 200개+잘림 표시, 기존 분류는 폼에 보완한다. 분류 자체의 생성/수정은 미완료다.
- 공개 변경 이력에 내용을 남긴다는 안내를 저장 전에 표시한다. 이력은 최신 20개 단위이며 요약·시각·행동·버전만 공개한다. 연결한 AP 계정, 회원 UUID, 비공개 인증 여부는 공개 작성자 정보로 사용하지 않는다.

## 동시 수정·복원

저장 시 읽었던 버전이 현재와 다르면 409로 거절한다. 입력을 버리지 않는다. 최신 내용을 불러와 비교하고, 서로 다른 필드의 수정은 합칠 수 있다. 같은 필드를 서로 다르게 수정했으면 원격 내용을 보여주고 별도 확인을 요구한다. 그 후에도 버전 검사를 다시 한다.

복원은 두 내용을 비교하고 이유와 확인 체크를 받아 새 버전으로 저장한다. 과거 이력은 지우지 않는다. 복원 도중 다른 수정이 들어오면 409이며 최신 비교를 다시 할 때 확인 체크가 해제된다. 이전 자료도 현재 입력 검증을 통과해야 한다. 예를 들어 분류가 전혀 없는 옛 버전은 그대로 복원하지 않고, 편집 화면에서 유효한 분류를 골라야 한다.

## DB·권한 경계

- migration 009는 기존 catalog_software의 컬럼을 바꾸지 않고 catalog_software_state와 catalog_software_edits를 추가한다. 내장 Diesel migration, 기존 프로세스/PG만 사용한다.
- 새 카탈로그 ID는 기존 bigint ID를 유지하며 짧은 PG advisory lock 안에서 할당한다. 새 도구의 등록자는 독점 편집권을 갖지 않는다.
- 쓰기마다 member → session → software → revision 상태 순서로 잠금/재검사한다. 로그아웃·차단된 회원의 오래된 세션 객체로 쓰지 못한다. 통상 편집에 15분 재인증을 요구하지 않는다.
- 기술적 도배 방지는 회원별 최근 1분의 성공한 쓰기 30회다. 회원 행 잠금으로 동시 우회도 막는다. 제품 정책/계정 연령 조건이 아니며 운영 부하를 보고 조정할 수 있다.
- 첫 편집 전에 옛 원본 전체를 baseline 0으로 보관한다. NULL/배열/메타데이터는 보존하며 공개 응답에는 편집 가능 필드만 선택한다. 원본이 1MiB를 넘으면 잘라 저장하지 않고 거절한다.
- 작성자 FK는 비공개 감사용이다. 회원 탈퇴 시 SET NULL로 분리하고 이력 내용은 남긴다. 일반 회원용 삭제 엔드포인트는 없다.
- locked 상태에서는 수정·복원을 거절한다. 관리자 역할·최초 관리자 부여·잠금 UI를 임의로 만들지는 않았다. 관리자 개입 화면은 별도 남은 작업이다.
- 오프라인 이관의 빈 대상 검사와 격리 결과 재검증에 새 두 테이블을 포함했다. 이관 후 편집 상태가 생겼다면 재이관으로 지우지 않고 불일치로 중단한다. 이력이 있는 migration 되돌리기는 명시적으로 거절한다.
