# 비공개 자료 이관 리허설

실제 백업의 집계, 보관 위치, 실행 환경과 승인 기록은 공개 저장소에 포함하지 않는다.
이 문서는 재현 가능한 검증 절차만 설명하며, 특정 운영 자료나 배포의 성공 증거가 아니다.

## 격리와 복원

1. 유지보수자가 승인한 백업만 사용하고, 원본과 체크섬을 보존한다.
2. 합성 시험용 trust DB와 분리된 비공개 PostgreSQL에 복원한다.
   접속 정보는 제한된 환경으로 전달하고 명령행·로그·저장소에 남기지 않는다.
3. 원본 manifest와 테이블·외래키·행 집계를 대조한다. 상세 결과는 비공개로 보관한다.
4. [이관 도구](legacy-import.md)의 dry-run, 적용, 동일 입력 재적용을 순서대로 검증한다.
5. 회원 UUID, 계정 귀속, 차단 상태, 관계, 서명키의 원문 바이트를 보존했는지 확인한다.
   오래된 작업 큐는 새 작업으로 재생하지 않는다.

## 파일과 활성화

DB의 파일 참조만으로 파일 보존이 끝난 것은 아니다. 별도 파일 사본을 확보하고
[파일 이관](legacy-assets.md)으로 실제 바이트를 대조한 뒤
[활성화](activation.md)를 검증한다. 검증 전 대상은 격리 상태로 유지한다.

합성 테스트 통과, 백업 무결성, 실제 복원, 파일 보존, 활성화, 공개 HTTPS와 로그인은
서로 다른 검증 항목이다. 하나의 성공으로 나머지를 완료 처리하지 않는다.

## 회귀시험으로 남기는 호환성

PEM 종단 개행을 포함한 기존 키는 원문을 바꾸거나 키를 재발급하지 않고 검증한다.
파싱용 view와 저장 바이트를 구분하고, 키쌍·비트 수·서명 검증 및 잘못된 키의
트랜잭션 롤백을 합성 fixture로 시험한다. 실사용 키나 회원 자료를 fixture에 복사하지 않는다.
