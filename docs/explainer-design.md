# 상세 설명 구현 · 검토용 2026-09-12

## 2026-09-13 후속 초안

주소 검색·팔로우(/start/find), 계정 이사(/start/moving, /guides/migration)를 각 세 장면의 선택형 스크롤 설명으로 추가했다. 필수 6단계 수업이 아니라 궁금한 상황을 고르는 주제다. 프로필도 social_demo의 공통 표면으로 만들었다. 모바일에서는 현재 제목/한 문장을 고정 창 아래에 붙여, 문장과 장면이 떨어져 보이지 않게 한다. 주소 찾기는 해당 단계의 창 하나, 결과를 비교하는 주제는 두 창을 유지한다. 아래의 ‘후속 후보/네 페이지’는 최초 구현 시점의 기록이다.

입력: 사용자가 전달한 설명 원고. 원본은 수정하지 않았다. 첫 인트로의 확장 방향은 살리고, 해설·요약의 반복과 여러 설정을 동시에 만지는 실습 패널은 줄였다. **랜딩, 회원 가입 연령, 인증·회원 로직, 서버 목록은 이번 변경 범위가 아니다.**

## 연출 기준

- 한 장면에 제목 하나와 짧은 보조 문장. 설명을 별도 카드·요약으로 반복하지 않는다.
- 첫 반전은 ‘옆에 다른 사이트가 있음’보다 **방금 대화하던 사람이 이 사이트 회원이 아니었다**는 사실이다. 대화 내용과 인물을 유지한다.
- SNS·주소·개인 홈페이지의 비유를 먼저 경험하고 규약 이름은 보충 설명으로 둔다.
- 사이트 발견에만 창의 크기와 배치를 바꾼다. 게시물의 전달은 방향 이동·패킷·화살표 없이 양쪽 글의 테두리로 표시한다.
- 네 페이지 모두 설명을 스크롤하면 고정된 비교 화면이 전환된다. 시간에 따라 자동 진행하지 않는다. 진행막대와 아래 화살표는 선택적 위치 바로가기이며, 별도의 버튼 상태나 지연 타이머로 장면을 바꾸지 않는다.
- 모바일에서도 두 사람의 결과를 함께 볼 수 있도록 비교 창을 세로로 압축한다. 설명은 창 아래를 지나며, 짧은 화면에서는 불필요한 앱 헤더와 보조 글을 숨겨 핵심 글·관계·열람 결과를 유지한다.
- 정상 스크롤을 가로채지 않는다. 앱 위에서 휠을 굴려도 페이지가 움직이며, 위로 스크롤하면 이전 장면으로 돌아간다. 모션 감소 설정에서는 확대·페이드를 없애고 같은 결과를 표시한다.
- 가짜 관리/게시 API 없음. 부가 메뉴 아이콘은 장식이다. 기존 앱 안의 ‘설정 바꾸기’·‘주소 열기’ 진행 버튼은 제거하고, 스크롤에 따라 해당 상황의 결과를 보여준다.

## 유지한 설정 / 분리한 코드

랜딩의 멍멍.개집·냥냥.타워·추억.사진·곰국.블로그, 슈나·페트리샤·골댕·필름·곰국을 이어 쓴다. 아이콘 계열도 Lucide / Heroicons Solid / Ionicons / Bootstrap으로 구별한다. **프레임·게시글·아바타·작성 창·블로그 UI와 제품별 스타일은 랜딩과 실제로 공유한다.** 자동 재생 상태는 랜딩에, 스크롤 상태와 장면 배치는 설명 페이지에 남긴다.

- `src/explainer/model.rs`: 문구와 단순 예제의 범위 계산. 서버가 아닌 팔로우 관계로 읽기 권한을 정하는 테스트 등 포함.
- `src/social_demo.rs`: 양쪽에서 쓰는 앱 창·게시글·아바타·작성 창·블로그 편집/발행/답글과 인물·사이트 설정. 앱의 아이콘 컨텍스트도 이 모듈이 소유한다. 중복 `src/explainer/sites.rs`는 제거했다.
- `src/explainer/mod.rs`: SSR 페이지·라우팅·상호작용.
- `assets/explainer-scroll.js`: 브라우저 위치 측정만 담당. 장면 상태는 Rust에 전달. DOM 변경 감시로 떠난 페이지의 리스너·ResizeObserver·애니메이션 프레임을 정리한다.
- `assets/styling/social-demo.css`: 승인된 랜딩의 제품 스타일을 추출한 단일 원본. 좁고 낮은 뷰포트의 `compact` density도 공통 스타일로 제공하며 색·아이콘·아바타·리스트/카드 구분은 바꾸지 않는다.
- `assets/styling/explainer.css`: 설명 문구·고정 스테이지·장면별 보임/숨김·비교 범위 표시만 담당한다. 제품 외양을 별도로 재정의하지 않는다. 랜딩의 모바일 창 교대는 `landing.css`에만 남는다.

SSR의 초기 장면은 서버·클라이언트가 동일하다. 네 페이지의 모든 짧은 문장과 주제 링크는 SSR HTML에 포함한다. 공통 스크롤 관찰은 마운트 후 실행한다.

## 정확성의 경계와 근거

아래는 2026-09-12 확인한 1차 문서다. 요점만 재구성하고 원문의 UI/표를 복제하지 않는다. 각 페이지의 ‘조금 더 정확히 알아두려면’에 근거 링크와 범위를 둔다.

- [W3C ActivityPub](https://www.w3.org/TR/activitypub/): 독립 서버 간 활동 전달. 기본 설명은 모든 웹사이트가 자동으로 연결된다는 뜻이 아니다.
- [Mastodon 네트워크 기능](https://docs.joinmastodon.org/user/network/): 팔로우, 알려진 공개 글, 전체 URL로 가져오기. 전달 페이지는 모든 배송 경로를 구현한 프로토콜 시뮬레이터가 아니다.
- [Mastodon 공개범위](https://docs.joinmastodon.org/user/posting/): 공개/팔로워/조용한 공개. 데모는 멘션 없는 새 글. 받은 내용의 복사나 운영자의 기술적 접근을 막는 암호화 보장이 아니다. 게시 후 회수를 의미하지 않는다.
- [Mastodon 개인 설정](https://docs.joinmastodon.org/user/moderating/), [운영자 설정](https://docs.joinmastodon.org/admin/moderation/): 뮤트와 관계 차단의 차이, 운영자 Suspend의 범위. 상대 사이트 삭제·웹 공개 원문까지 완전 차단하는 것으로 표현하지 않는다. 되감기는 설정 해제나 팔로우 자동 복구가 아니다.

가상의 앱은 특정 제품의 이름·UI와 일치시키지 않는다. 다른 제품에서도 모든 권한과 차단 방식이 같다고 주장하지 않는다. 보충 설명을 펼치지 않아도 중요한 개인정보 경계 문장은 공개범위 장면 아래에 남긴다.
