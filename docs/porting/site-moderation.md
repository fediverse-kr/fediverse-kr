# 사이트 관리자 — 2026-09-14

기존 MIT Phoenix `admin_live.ex`의 서버 관리 이벤트를 기준으로 포팅했다.
같은 관리자 역할을 쓰며, `/account/moderation/sites`와 상세 `/account/moderation/sites/:id`로 들어간다.
내 계정과 신고 관리에 관리자 메뉴를 함께 노출한다. `/admin/servers`는 새 목록으로 308 이동한다.

## 연결한 기능

- 숨김/강제 숨김/종료를 포함하는 전체 서버 목록, 이름·도메인 리터럴 검색,
  상태 필터, 도메인/등록일/회원 수 정렬, 24개 페이지. 상세 정보가 아직 없는 신규 서버도 조회한다.
  조회만으로 보조 행을 만들지 않는다. 검색 128자/512바이트, 페이지 최대 10,000.
- 일반 숨김, 강제 숨김, 운영 종료, 초대제(미확인 포함), 태그를 **각각 따로** 변경한다.
  소개·규칙·언어·코멘트·소유권·원격 관측값은 관련 없는 조치로 덮어쓰지 않는다.
- 일반 숨김은 오너도 변경 가능하다. 강제 숨김은 관리자만 해제한다.
  두 숨김은 공개 목록/상세/아이콘에서 제외되지만 수집은 계속한다.
  종료는 정기 수집/운영 중 통계에서 빠지며, 숨김이 없으면 공개 목록에 남는다.
- 수동 수집은 **같은 PG 큐**에 요청한다. 완료됐다고 즉시 표시하지 않고 실제 작업 상태를 읽는다.
  오너와 관리자 요청이 같은 서버별 1시간 제한을 공유한다. 종료 서버의 일회 수집을 허용하되
  종료 플래그는 유지한다. 새 큐·프로세스·컨테이너는 없다.

## 권한·동시성·보존

- API/SSR는 비공개 no-store이다. DTO에 외부 연동 주소, 세션, 원본 전체 snapshot은 넣지 않는다.
- 조치마다 현재 DB의 회원/세션/차단/관리자 역할 및 15분 재인증을 확인한다.
  권한 회수 직전의 화면이나 오래된 세션을 신뢰하지 않는다. Origin·실제 8 KiB 본문 제한을 적용한다.
- 조치 사유 1~1,000자/4,000바이트와 명시적인 확인이 필요하다. 태그는 기존 오너 입력 검증을 공유한다.
- lock 순서: 관리자 gate → 관리자 회원/세션 → 사이트 → 상세.
  오너와 같은 revision을 비교하므로 관리자/오너가 동시에 저장하면 하나만 성공한다.
  충돌 시 사유 초안을 보존하며 최신 상태를 확인하고 조치를 다시 선택해야 한다.
- 원본 `directory_site_edits.previous`에 조치 전 모든 사이트/상세 값을 보존한다.
  migration 015는 여기에 관리자 사유와 형식이 정해진 변경 요약만 추가한다.
  원래 DNS/API 인증·오너 편집/사임/탈퇴 이력도 유지한다.
- 관리자 조치마다 revision을 올린다. 수동 수집 요청도 감사 가능한 revision을 가진다.
  오너의 기존 수동 수집은 원래 의미대로 revision을 올리지 않지만 같은 큐 예약 함수와 제한을 쓴다.
- 실제 변경이 없는 조치는 권한과 revision 검사를 거친 뒤 이력/버전을 추가하지 않는다.
- 태그의 변경 여부는 표시 문자열이 아니라 원래 배열로 비교한다. 쉼표를 포함한 옛 태그 한 개와
  별개의 태그 두 개가 같은 문자열로 보이더라도 교체를 건너뛰지 않는다. 이력에는 개수도 표시한다.
- 긴 옛 태그는 화면·요약에서 600자까지만 표시한다. 다른 필드 조치에서는 원본 그대로 보존한다.
  태그 교체를 선택했을 때는 전체 교체임을 안내하고 새 입력 상한을 적용한다.
- 관리자 탈퇴 시 이력의 작성자 연결만 NULL이 되며 사유·이전 값은 남는다.
  관리 이력이 있는 격리 DB는 재이관으로 초기화하지 못한다.
  015 downgrade도 관리자 이력을 조용히 버리지 않고 거부한다.

### 사이트 삭제 계약 (migration 024)

- 물리적 사이트 삭제는 관리자 현재 권한과 15분 재인증을 다시 확인한 뒤에만 수행한다. 요청에는 사이트 UUID, 현재 revision, 정확한 domain, `confirmed=true`, 1~1,000자의 삭제 사유가 모두 필요하다. 없는 대상은 404, 현재 잠금 행의 UUID/revision 불일치는 409로 거부한다.
- 삭제 대상은 이 로컬 서비스의 사이트와 projection이다. 원격 서버에 삭제를 요청하거나 원격 데이터를 지우지 않는다. 댓글·답글, 사이트 편집 이력, `legacy_health_checks`, runtime legacy projection, owner challenge를 삭제한다. 공유 favicon은 보존하며 마지막 참조가 없어진 파일만 기존 `media_cleanup`/OpenDAL 경로로 retire한다.
- 신고와 기존 증거는 보존한다. 삭제된 댓글을 가리키던 신고의 연결만 해제하며, 새 `site`/`delete_site` moderation audit에는 UUID·revision·삭제된 댓글/health 수·보존된 신고 수와 사유만 남긴다. 삭제 audit 자체는 사이트 FK에 의존하지 않는다.
- 원본 백업, export/import inventory는 변경하지 않는다. 이 범위는 Phoenix MIT 원본의 FK 관계와 일치하며, migration 024의 downgrade는 사이트 삭제 audit가 남아 있으면 조용히 되돌리지 않는다.

## 별도로 남은 기능

- 실제 운영 자료의 관계·저장 파일 대조와 운영자 승인은 별도 남아 있다. 합성 자료의 실제 HTTP/PG 삭제 및 신고 보존, Linux 배포물 검사는 [통합 기록](integration-checks.md)을 따른다.
- 소프트웨어 로고와 공개 이력의 제한 열람, 실제 운영 관리자 지정. 종류·잠금·관리자 편집은 후속 [카탈로그 관리](catalog-moderation.md)에서 연결했다.
- 옛 모든 변경 이력의 표시와 되돌리기 UI. 지금 목록은 새 버전의 관리자 조치만 표시한다.
- 실서버 수동 수집 성공, 실회원/실데이터 이관, Linux 배포는 별도 검증이다.

집중 PG 7개, 최종 전체 146개, 사이트 관리자 브라우저 55개가 통과했다. 기존 신고 40개·운영자 47개와 실제 CLI 권한 회수 후 접근 차단도 확인했다. [integration-checks.md](integration-checks.md)에 실행 경계와 미완료를 구분했다.
