# Phoenix 교체 준비 — 실행 현황과 검토 묶음

2026-09-14. 목표: 기존 Phoenix를 내리고 이 버전으로 대체. 아직 cutover 불가.
승인된 랜딩 외에는 사람 검토 전 초안을 채우되, 미구현 기능을 구현된 것처럼 보이지 않게 한다.

## 이번 보강

- [비공개 백업 ZIP 준비](porting/private-archive.md): 라이브러리로 AES 해제·무결성
  확인을 수행하고 접근이 제한된 별도 배치에 보관한다. 정상/변조/경로/누락 등 합성
  **64개**, 공통 권한 코드 분리 후 빈 PG 준비 **14개** 통과. 초기 SharpCompress의
  AES 인증값 변조 수용을 발견해 MIT SharpZipLib로 교체했고, 옛 검증 기록은 거절한다.
  실제 백업은 암호 대기로 아직 복호화·복원하지 않았으며 운영 서비스도 변경하지 않았다.

- [배포 라이선스 고지](porting/third-party-notices.md): cargo-about으로 server/web를 따로
  분석하고 원문·NOTICE·아이콘·폰트 고지를 실제 이미지에 포함했다. 생성기 합성 **10개**,
  Windows/Linux context 각 **27개**, 실제 ELF/OCI **208개** 통과. 선언만 확인된 라이브러리
  **7개**는 경고로 남겼다. OS 이미지/출처 미확정 자산의 검토나 실자료 컷오버 완료는 아니다.

- [DB 전용 사설 CA TLS](porting/postgres-tls.md): 기존 라이브러리로 선택형 CA 파일을 연결했다.
  실제 Linux TLS PG **47개**, Windows 전체 Rust/PG **250개**, Linux 배포물/OCI/집중 검사
  **205개** 통과. 인증서/호스트 오류와 평문 downgrade를 거절하며 기존 개발 연결은 유지한다.
  실제 운영 DB 접속이나 실회원 데이터 이관을 끝냈다는 뜻은 아니다.

- [단일 프로세스 OCI 배포](../deploy/container/README.md): 서버와 웹 파일만 담는 이미지와
  제한된 context 준비 도구를 추가했다. 실제 ELF/컨테이너 **204개**, 합성 context **17개** 통과.
  read-only rootfs에서 HTTP·워커·OpenDAL 업로드/재시작/삭제와 SIGTERM을 확인했다.
  운영 환경의 볼륨 권한/TLS/AP·이미지 서명·실백업 전환은 남아 있으며, 로컬 빌드만 했다.

- [수집 아이콘 호환·실제 공개 정보 조회](porting/integration-checks.md): SVG 저장을 막던
  DB 제약을 내장 migration 025로 보완하고 이관 favicon의 자동 재수집을 막았다.
  Windows 전체 Rust/PG 243개, 브라우저 SVG 21개/PNG 18개, Windows 실행 127개와
  Linux 실행 125개/집중 Rust 21개가 통과했다. Mastodon·Misskey 실제 공개 NodeInfo 조회도
  확인했지만, signed AP/실회원 인증·실백업·운영 전환 검증은 아니다.

- [기존 이미지/이모지 호환](porting/media-serving.md): 원본 shortcode와 파일명 제한을
  혼동해 일부 이모지를 숨기던 문제를 수정했다. 기존 `image` 라이브러리로 AVIF/BMP/TIFF
  형식도 판별한다. Rust 집중 27개, 실제 이관·활성화/HTTP 127개, Linux 실행 121개,
  브라우저 89개 통과. 실제 백업의 이미지 전수 대조를 완료했다는 뜻은 아니다.

- [실자료용 비공개 PG 준비](porting/private-import-cluster.md): 개발 trust DB와 별도로
  Windows 사용자/SYSTEM 전용 저장 경로, SCRAM·loopback 접속, 로그 제한, 빈 사본 DB를
  준비하는 도구와 거절/종료 회귀 검사 **14개**를 확인했다. 테스트 PG는 중지했다.
  실제 ZIP은 여전히 암호 대기이며 복원하지 않았다. 중단된 실행의 비공개 임시 파일
  한 개는 도구 정책상 정리하지 못한 상태로 위 문서에 기록했다.

- [기존 actor/inbox 계약](porting/actor-compatibility.md): 원본과 현재 공개 응답을
  대조해 inbox 광고·host 이름·빈 202 응답을 복원했다. 실제 활동 수신 처리로 확장하지
  않으며 이관 키/ID와 회원 인증 경계는 유지한다. Windows·Linux 배포물로 확인했다.

- [관리자 사이트 삭제](porting/site-moderation.md): 원본처럼 등록 항목·댓글·수집 기록을
  삭제하고 신고·증거는 보존한다. 정확한 도메인·확인·사유와 최근 인증을 요구하며,
  삭제 중 수집 결과와 공유 파일을 보호한다. 내장 migration 24개, 실제 합성 자료로 검증했다.

- [관리자 전체 프로필 갱신](porting/profile-media-refresh.md): 원본의 누락된 일괄 갱신을
  기존 관리자 메뉴/공통 AP·OpenDAL/같은 프로세스의 PG 워커에 연결했다. 시작·진행·중단과
  재시작 회수, 선택 출처·이름·비공개 설정 보존을 포함한다. 내장 migration 23개.

- [내 댓글](porting/community.md): Phoenix 내 페이지에서 빠졌던 개인 기록을 계정 메뉴에 연결했다.
  구 회원 UUID의 댓글·답글, 숨김 서버의 본인 기록, 삭제 제외, 비로그인/세션 폐기 후 차단을 확인했다.

- [서버 응답 이력](porting/server-discovery.md): 기존 Phoenix의 최근 48회 범위를 상세 페이지에
  연결했다. 이관된 기록/현 수집 기록을 같은 DB 조회로 표시하며, 숨김 제외·시각/소요 시간·빈 기록,
  모바일과 키보드로 펼치는 상세 표를 확인했다. 별도 큐·차트 라이브러리·migration 추가는 없다.

- [회원 사진·이모지 갱신](porting/profile-media-refresh.md): 공개 AP 인증 후 자동 수집과
  계정 화면의 출처 선택/수동 갱신을 AP·실제 PG·OpenDAL에 연결했다. 이름/공개 설정을 바꾸지 않으며
  실패 시 기존 이미지, 이관 원본과 공유 파일을 보존한다. 내장 migration 22개.

- [제품 로고 관리](porting/catalog-logos.md): 기존 관리 화면에서 파일 선택→저장→공개 표시,
  교체·삭제, 충돌 시 입력 보존까지 OpenDAL/실제 PG에 연결했다. 이미지 디코딩은 `image`를 쓰고
  기존 파일 보존과 같은 publication 경로를 재사용한다. AP 이미지 재수집은 위 후속을 따른다. S3는 별도다.

- [소프트웨어 공개 검색·페이지](porting/catalog-browsing.md): 처음 500개 안에서만 찾던
  클라이언트 필터를 전체 DB 조회로 교체했다. 종류부터 고르는 구성과 공통 UI는 유지하며,
  URL·뒤로 가기·SSR, 24개 제품·12개 종류 페이지와 독립적인 종류 이름 조회를 연결했다.

- [Linux 배포물·종료 검증](porting/release-lifecycle.md): 실제 ELF와 웹 자산의 SSR/HTTP,
  같은 프로세스 워커, SIGTERM·느린 요청 종료를 확인했다. 시작 실패 전 워커 실행 순서와
  회원/서버 경합의 교착 상태를 수정했다. 운영 호스트/TLS/실자료 전환은 별도 남아 있다.

- [검토된 사본 활성화](porting/activation.md): `--legacy-activate`의 검사/명시적 적용,
  원본·보존 행·projection·파일 전수 재대조, DB 이름/origin에 묶인 승인과 시작 시 저장소 검사를 추가했다.
  기존 격리 표식은 지우지 않는다. 실제 운영 자료 활성화·Phoenix 중단·트래픽 전환은 하지 않았다.

- [이미지 런타임 조회](porting/media-serving.md): 내장 migration 018로 파일 매핑을 연결하고
  공개 로고/서버 아이콘과 본인 전용 아바타/이모지를 실제 저장 바이트로 표시한다.
  [OpenDAL·인증 비교·Cookie·URL·XML 라이브러리](porting/library-boundaries.md)로 범용 처리를 교체했다.
  로고 업로드와 AP 이미지 재수집은 위 후속으로 연결했다. 실제 백업 검증·S3·운영 활성화는 남았다.

- [탈퇴 후 파일 정리](porting/media-cleanup.md): 내장 migration 020의 PG 예약과 같은
  프로세스의 OpenDAL 삭제를 연결했다. 공유 키·공유 바이트는 보존하고 오류는 재시도한다.
  원본 export/이관 inventory/백업을 지우지 않는다. 로고 업로드와 같은 파일 잠금을 사용하며
  AP 이미지 재수집의 새 파일도 같은 정리 경로를 사용한다.

- [기존 파일 보존 묶음](porting/legacy-assets.md): 같은 바이너리의 오프라인 명령으로
  아바타·이모지·파비콘·소프트웨어 로고 참조를 대조하고, 별도 export의 원본 바이트와
  내용 해시/길이를 보존한다. 기존 파일 덮어쓰기·자동 웹 공개·운영 활성화는 하지 않는다.
  실제 백업 검증은 남았고 운영 이미지 조회의 현재 범위는 위 후속을 따른다.

- [소프트웨어 관리자·종류 관리](porting/catalog-moderation.md): 회원 편집 화면 재사용, 잠금 중 관리자 수정, 메타데이터/로고 개별 변경, 분류 추가·수정, 비공개 사유/이력, 공통 revision 충돌 검사를 연결했다. 공개 이력의 제한 열람 처리 등은 남았다.

- [사이트 관리자](porting/site-moderation.md): 전체/숨김 서버 조회·검색/정렬, 일반 숨김·강제 숨김·종료·초대제·태그 개별 변경, 오너와 공유하는 수집 큐/1시간 제한, 사유·이력과 revision 충돌 검사를 화면/DB에 연결했다.
  관리자 물리 삭제도 연결했다. 대상 댓글·답글·응답 기록·런타임 이관 행·운영자 인증·편집 이력을
  지우고 신고·기존 증거·삭제 감사 기록·원본 백업/export/inventory는 보존한다.
  공유 favicon은 보존하며 마지막 참조가 없어진 파일만 기존 OpenDAL 정리 경로로 보낸다.
  원격 서버는 변경하지 않는다. 실제 운영 데이터 삭제를 검증했다는 뜻은 아니다.

- [관리자 권한·신고 처리](porting/moderation.md): 내부 회원 UUID 역할, 신고 상태 필터/검토/처리·기각·재검토, 댓글 삭제 표시·작성자 차단/해제, 비공개 이력과 충돌 거절을 DB/화면에 연결했다. 같은 바이너리의 명시적 grant/revoke CLI만 역할을 변경한다. 실제 관리자를 지정하거나 사이트·소프트웨어 관리자 기능 전체를 완성한 것은 아니다.

- 신규 서버 등록을 `/account/sites/new`와 서버 찾기/관리 화면에 연결했다. 서버 정보 확인→미리보기→재확인 후 등록이며, 등록자에게 운영자 권한을 주지 않는다. 중복/숨김 보존, 비공개 귀속, 첫 수집 PG 작업까지 원자적으로 저장한다. [등록 계약과 6개월 정책 검토 상태](porting/site-registration.md).
- 기존 회원 첫 로그인: Phoenix 소스와 같은 정규화 주소의 새 공개 인증글 검증 뒤 옛 UUID·표시 이름·가입 시각·댓글·서버 권한을 이어받는다. 최초 검증 actor ID를 고정해 이후 주소 재사용/다른 회원 병합/연결 해제 후 익명 복구를 막는다. [신뢰 한계와 검증 범위](porting/legacy-member-login.md). 실제 회원 DB나 운영 활성화까지 완료한 것은 아니다.
- 댓글·답글·수정·삭제·신고를 서버 상세/실제 PG에 연결했다. 기존 1분 간격·30분 수정 규칙, 비공개 연동 보호, 충돌 검출, 변경 알림과 신고 시점 원문 보관을 포함한다. 관리자 전용 원문 검토와 처리도 후속 연결했다. [계약과 남은 범위](porting/community.md).
- 소프트웨어: 회원 직접 등록·수정, 공개 변경 이력, 버전 비교·복원, 동시 편집 충돌 해결을 화면과 DB에 연결했다. 별도 승인함이나 6개월 조건을 추가하지 않았다. 비공개 연동 계정은 공개 이력에 노출하지 않는다. [편집 계약과 미완료](porting/software-contributions.md).
- 서버 찾기: 종류·계열·소프트웨어·태그·가입/응답 상태 필터, 고정 기준 정렬, 결과/제외 개수, URL 보존과 페이지 크기를 실제 DB 조회로 연결했다. 추천은 제외. 수집 아이콘 서빙과 소프트웨어 상세의 독립 조회도 연결했다. [조회 계약과 남은 범위](porting/server-discovery.md).
- 서버 운영자: DNS TXT 일회용 인증, 소유 서버 페이지, 직접 소개/규칙/태그/초대·승인/코멘트 수정·숨김, 충돌 검출·비공개 변경 이력, 사임·탈퇴 연결. 옛 운영자/안내를 별도 live projection으로 이관한다. [구현과 미완료](porting/site-ownership.md).
- 연동 AP 계정 기반 Mastodon contact/Misskey isAdmin 운영자 인증과 1시간 제한 PG 수동 갱신·실제 작업 상태 조회를 추가했다. DNS 우선순위와 기존 회원 공개 인증글 방식은 유지. 새 패키지나 컨테이너는 없다.
- 회원 관리 후속 통합: 표시 이름·연동별 공개 설정 저장, 마지막 로그인 보호와 연결 해제, 기존 AP 계정 재인증을 통한 암호 복구, 탈퇴 화면/DB 처리. [세부 범위와 남은 경계](porting/member-lifecycle.md).
- 소프트웨어 종류 → 목록 → 상세 → 해당 소프트웨어 서버 목록을 SSR 화면으로 연결.
- 공개 서버 목록/상세/통계를 Diesel 조회로 연결. 숨김/강제 숨김은 DB 조회 단계에서 제외. 목록 24개 페이지 나눔, 검색 문자열은 SQL wildcard가 아닌 리터럴.
- DB 미설정일 때만 명시적인 예시. 설정 오류/조회 실패 시 예시로 전환하지 않음.
- 서버 응답 시각 / 메타데이터 시각을 분리. 알 수 없는 수치는 알 수 없음. 운영 종료는 목록에 표시하되 운영 중 통계에서 제외 (기존의 단순 전체 합계와 차이).
- 메뉴 여섯 개 노출, 계정 별도. 운영·개발·사람·앱·사이트 안내를 실제 경로에 채움.
- 기존 네 설명에 주소 검색·팔로우 및 이사의 스크롤 3장면씩 추가. 가상 앱 창/프로필/게시물을 공통 컴포넌트로 사용.
- /software→/platforms, /my→/account, 구 인증 GET→/login, /recommend→/servers HTTP 308. 구 인증 query는 전달하지 않음.
- /healthz, /readyz. readiness는 DB 연결 확인이지 cutover 승인 아님.
- 없는 페이지·소프트웨어·공개 서버 정보는 HTTP 404, 조회 장애는 503. 조회 입력 상한 오류는 400.

회원용 6개월 상세 기준과 서비스 분쟁 운영 정책은 미정이다. 이와 무관한 ORM·이력·권한 경계·UI 초안은 진행할 수 있다. 사람의 정책 결정을 기다린다는 이유로 모든 개발을 멈추지 않는다.

2026-09-14 회원 원본 재대조: Phoenix `router.ex`에는 공개 회원 프로필·사람 목록 경로가
없으며 `my_live.ex`에는 내 댓글, `admin_live.ex`에는 전체 회원 프로필 재수집이 있다.
내 댓글과 관리자 전체 재수집을 연결했다.
공개 프로필·사람 찾기는 사용자가 검토할 새 기획으로 구분한다. 새 기획을 전부 출시 수준으로
확장해야만 기존 앱 교체가 가능하다고 간주하지 않는다. 다만 요청된 초안·검토 동선 자체는
목표에 계속 포함되며, 실회원 데이터/인증/운영 전환 검증은 여전히 완료되지 않았다.

## 운영 전환 전 순서

1. 연결된 회원·관리·댓글 기능의 합성 PG/HTTP 검증 결과를 검토하고, 실자료 시나리오를 확인.
2. 새 버전의 독립된 private PG에 스냅샷 복원, importer dry-run 및 원본 대조. 현 개발 trust 클러스터 금지.
3. 구 회원 귀속·ban·오너·댓글·숨김·키·이미지 전수 대조. importer quarantine을 임의 제거하지 않음.
4. Linux에서 동일 바이너리 HTTP/워커, TLS/프록시/세션/AP 공개키 접근을 검증.
5. 검토 승인 뒤 유지보수 창에 쓰기 정지→최종 백업→차이 반영→재대조→트래픽 전환.
6. 되돌릴 때 새 버전의 쓰기를 먼저 막고, 전환 이후 쓰기 차이를 보전한 뒤 Phoenix로 복귀. 단순 이미지 롤백으로 양쪽 DB 일관성을 보장할 수 없음.

실제 DB/ZIP의 행을 아직 읽지 않았다. 외부 계정에 게시하거나 Phoenix를 중단하지 않았다.
