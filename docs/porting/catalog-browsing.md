# 소프트웨어 공개 목록 — 2026-09-14

종류 → 소프트웨어 → 해당 서버로 이어지는 기존 구성을 유지한다. 처음 받은 500개를
브라우저에서 거르던 방식은 제거했다. 회원이 뒤늦게 추가한 소프트웨어도 전체 DB에서 찾는다.

## 조회 계약

- `/platforms?q=검색어&cat=종류&page=2&kind_page=2`. 화면과 URL의 페이지는 1부터,
  내부 모델은 0부터 센다. 검색어·선택 종류·두 페이지는 공유/새로고침/뒤로 가기에 남는다.
- 소프트웨어는 24개, 종류는 12개씩. 종류를 바꾸거나 검색하면 소프트웨어 첫 페이지로
  돌아가고, 종류 목록의 페이지 위치는 보존한다. 메뉴나 등록 링크를 숨기지 않는다.
- 새 `/api/public/software-search?filters=...`는 같은 `CatalogQuery`를 사용한다.
  URL 인코딩/디코딩은 기존 `url` 라이브러리, 입력 계약은 도메인 모델이 담당한다.
- 이름/식별자에 대한 대소문자 무시 리터럴 부분 검색이다. `%`, `_`, `+`는 wildcard가 아니다.
  종류는 정확히 일치시킨다. 옛 빈 `categories`의 `category_tag` 대체도 유지한다.
- Diesel adapter의 read-only repeatable-read 트랜잭션에서 결과 수·카드·종류·표시 이름을
  읽는다. 정렬은 `display_order, lower(display_name), name`으로 동률에도 확정적이다.
  페이지 간 수정이 없는 경우 중복/누락이 없다. 다른 요청 사이의 신규 등록/수정까지 고정하는
  장기 스냅샷은 아니며, cursor pagination으로 가장하지 않는다.
- 카드와 선택한 종류의 이름은 종류 페이지와 별도 조회한다. 201번째 종류를 고른 제품도
  원시 식별자 대신 표시 이름이 나온다. 기존 공개 필드 allowlist를 그대로 사용한다.
- 검색어 256바이트, 종류 128바이트, 내부 페이지 10,000 이하, 전체 query 2,048바이트.
  중복 키/제어문자/범위 오류는 API와 SSR에서 400. 유효하지만 빈 페이지는 복귀 링크를 준다.
- DB 미설정일 때만 명시적 예시다. 설정된 DB 장애는 503이며 예시로 바꾸지 않는다.
- 페이지/종류는 실제 링크이고 SSR에 결과를 포함한다. JavaScript 없이도 이동 가능하다.
  검색 폼은 기존 hydration 준비 조건을 유지한다.

기존 `/api/public/catalog`의 200종류/500제품 + `truncated` 응답은 호환용으로 남긴다.
주 화면은 더 이상 이 엔드포인트로 검색하지 않는다. 관리자/회원 편집 폼의 분류 선택지
상한은 별개의 후속 범위이며, 이번 작업으로 모든 선택란을 페이지화한 것은 아니다.
