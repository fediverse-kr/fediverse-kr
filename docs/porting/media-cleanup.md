# 탈퇴 후 파일 정리 — 2026-09-14

MIT Phoenix reference `accounts/accounts.ex:withdraw_user/1`의 아바타·이모지 삭제를
새 회원 수명주기에 연결했다. 탈퇴 응답은 **회원과 파일 참조 제거의 완료**이며,
물리 파일 삭제까지 동기적으로 끝났다는 약속은 아니다.

## 경계

1. 최근 인증을 다시 확인한 탈퇴 트랜잭션에서 해당 회원의 아바타·이모지 키를 확보한다.
2. 기존 회원·댓글·운영자 정리를 수행한 뒤, 더는 참조하지 않는 `stored_files` 매핑만 제거한다.
   다른 회원의 아바타/이모지, 사이트 아이콘, 소프트웨어 로고 참조는 모두 남긴다.
3. 제거된 매핑의 해시·길이를 내장 migration 020의 `media_deletions`에 같은 트랜잭션으로
   기록한다. 원래 경로·회원 식별자는 큐에 넣지 않는다. 트랜잭션 실패 시 예약도 롤백된다.
4. 같은 서버 프로세스의 정리 워커가 현재 매핑을 다시 검사한다. **다른 키라도 같은 바이트를
   쓰면 삭제하지 않는다.** 마지막 참조가 없어졌을 때만 OpenDAL `Operator::delete`를 호출한다.
5. 성공하면 예약을 제거한다. 이미 없는 개별 파일도 성공이다. 변조·권한·저장소 오류는
   예약을 남기고 1분부터 최대 1시간 간격으로 재시도한다. 원문 오류·경로는 로그에 남기지 않는다.

탈퇴 HTTP 요청 중에는 파일 IO를 하지 않는다. 응답 연결이 끊겨도 커밋한 삭제 예약은 남는다.
실제 삭제 뒤 DB 확인 전에 중단되어도 다음 실행에서 ‘이미 없음’을 확인하고 마친다.
새 프로세스·컨테이너·브로커·범용 큐 프레임워크는 추가하지 않았다.

## 동시성과 저장소 계약

- 매핑 정리와 워커는 `stored_files`의 `SHARE ROW EXCLUSIVE` 잠금 순서를 공유한다.
  두 회원이 동시에 같은 이모지 키를 놓아도 마지막 참조를 놓치지 않는다. 일반 읽기는 막지 않는다.
- 워커는 한 번에 하나의 파일만 처리한다. 잠금을 즉시 얻지 못하면 supervisor에서 backoff한다.
  파일 IO가 끝나기 전에 timeout으로 떼어놓고 성공 처리하지 않는다. 중단 시 DB 확인은 롤백한다.
- [제품 로고 업로드](catalog-logos.md)부터 런타임 쓰기가 생겼다. 실제 워커는 PG 잠금 전에
  같은 `.runtime.lock`의 OS 잠금을 소유한다. OpenDAL blocking IO가 그 핸들을 함께 보유하므로
  DB 잠금 해제/요청 취소 뒤에도 진행 중인 파일 삭제와 새 게시가 겹치지 않는다.
  이는 **현재의 로컬 Fs 전용** 계약이며 S3나 잠금이 보장되지 않는 공유 볼륨의 보장은 아니다.
- `ObjectStore`는 절대 경로, 링크/정션, 정규 해시·길이, 16 MiB 상한과 실제 SHA-256을 검사한다.
  경로 입력이나 재귀 삭제를 받지 않는다. `objects` 디렉터리 자체의 누락은 개별 파일 삭제
  성공으로 간주하지 않는다. 신뢰하지 않는 로컬 프로세스가 경로를 갈아끼우는 OS sandbox는 아니다.
- 활성화된 DB에 미완료 예약이 있으면 시작 시 저장소 설정이 필요하다. 저장소가 없는 개발
  실행에서는 예약만 보존되고 실제 정리는 실행하지 않는다.

## 백업·이관 기록은 별개

`FEDKR_MEDIA_DIR`로 활성화한 파일 묶음은 이후 **변경 가능한 운영 저장소**다.
활성화 전에 독립적인 DB/파일 백업을 보존해야 한다. 원본 export, 실제 제공된 ZIP,
이관 당시 `legacy_asset_files`/manifest는 이 워커가 수정하지 않는다.

탈퇴 이후 시작 검사는 현재 `stored_files`만 확인한다. 과거 파일이 사라졌다는 이유로
정상적인 재시작을 막거나, 승인 재시도가 옛 회원/매핑을 되살리지 않는다.
백업에서의 개인정보 보존·삭제 주기는 별도 운영 정책이며 이 구현이 자동 삭제하지 않는다.
댓글 본문·신고·변경 이력도 기존 방침대로 보존된다. 완전한 데이터 소거라고 표현하지 않는다.

## 검증

가상 회원·가상 파일·격리 PG로 공유 키/공유 해시, 동시 탈퇴, 롤백, IO 실패와 재시도,
새 연결의 작업 재개, IO 이후 확인 중단, 파일 변조/누락/경로 이탈 거절을 검사한다.
실제 배포물 검사에도 HTTP 탈퇴 → 같은 프로세스의 파일 삭제 → 재시작을 넣었다.
실행 시점별 성공/실패는 [통합 검사 기록](integration-checks.md)을 따른다.

공식 동작 근거: [OpenDAL 개별 파일 삭제](https://opendal.apache.org/docs/rust/opendal/struct.Operator.html#method.delete),
[PostgreSQL 잠금](https://www.postgresql.org/docs/14/explicit-locking.html#LOCKING-TABLES).
