# 서버 댓글 · 답글 · 신고

2026-09-13. 기존 Phoenix MIT 소스의 동작을 기준으로 서버 상세에 연결했다.
실회원 ZIP은 사용하지 않았다. 2026-09-14 [관리자 판정과 조치 이력](moderation.md)을 후속 연결했다.

## 옮긴 규칙과 경계

- 공개 서버 상세에서 댓글, 한 단계 답글, 페이지 나눔을 제공한다. 숨김·강제 숨김은 DB 조회/쓰기 시 다시 확인한다.
- 댓글은 2,000자, 같은 회원·서버에 1분 간격. 삭제한 댓글도 간격 제한에 포함된다. 수정은 작성 후 30분까지, 삭제는 이후에도 가능하다.
- 원래 문서에는 마크다운이라고 쓰여 있지만 `server_detail_live.ex`의 실제 렌더링은 일반 텍스트다. 현재도 일반 텍스트로 표시하고 HTML을 실행하지 않는다.
- 표시 이름은 공개한다. 비공개 SNS 연동 주소, actor, 회원 UUID, 로그인 ID는 댓글 DTO에 포함하지 않는다. 쓰기 직전에 이름 공개를 안내한다. 권한 조회는 hydration 이후 별도 private API다.
- 본인이 수정·삭제할 수 있다. 수정 시각을 정확한 revision으로 사용해 동시 수정을 덮어쓰지 않는다. 삭제 확인도 확인창을 연 시점의 revision에 묶는다.
- 삭제/탈퇴 댓글은 공개 SQL 결과에서 본문과 이름을 비운다. 답글은 남으며, 원문·신고는 비공개 보관한다. 완전 삭제라고 표현하지 않는다.
- 신고 이유는 원래의 스팸/괴롭힘/주제 이탈/기타 네 가지, 설명은 500자다. 본인/삭제 댓글은 신고할 수 없고 중복 신고는 거절한다. 접수는 `pending`이며 즉시 삭제나 처리 완료를 의미하지 않는다.
- 신고 시점의 원문·이름·수정 시각을 비공개 증거 테이블에 저장한다. 이후 수정/삭제가 신고 당시 내용을 바꾸지 않는다. 후속 관리자 전용 검토 화면에서 현재 댓글과 구별해 열람한다.
- 새 기술적 방어로 회원당 분당 신고 요청 30개를 제한했다. 이는 계정 연령/등급 정책이 아니다.

## 내 댓글 — 2026-09-14 후속

- Phoenix `MyLive` → `Discussions.list_comments_for_user/1`의 개인 기록을
  `/account`의 ‘내 댓글’ 링크와 `/account/comments`에 연결했다.
- `/api/member/own-comments?page=0`은 인증 세션의 회원 UUID만 사용한다. 다른 작성자를
  지정하는 입력은 없다. DB에서 세션 만료/폐기/ban을 재검사하며 API와 SSR은
  `private, no-store`와 `Vary: Cookie`를 사용한다. 비로그인 화면에는 로그인 안내만 나온다.
- 본인 댓글·답글의 최신순 20개 페이지, 삭제 표시 제외, 동률 UUID 정렬이다. 목록은
  원본과 같은 짧은 본문 미리보기이며 2,000자 초과 이관 자료는 원문을 보존한다.
  기존 글에는 같은 UUID로 로그인하면 접근한다. 타인 답글·연동 주소·신고 내용은 포함하지 않는다.
- 숨김/강제 숨김 서버에 남긴 본인의 글과 서버 주소는 이 비공개 개인 목록에 남는다.
  숨김 서버의 공개 링크는 만들지 않는다. 공개 댓글 조회와 숨김 정책을 완화하지 않았다.
  공개 서버 링크는 기존 서버 상세/댓글 컴포넌트로 이동한다. 별도 수정·삭제 UI를 복제하지 않는다.
- 기존 author index, 회원 guard, Dioxus SSR/페이지·스타일을 사용한다. 새 라이브러리,
  migration, 작업 큐는 없다. 새 공개 프로필이나 팔로워 목록을 만드는 기능이 아니다.

## 실행 구조

`community` DTO/UI → `backend/community` 규칙 → `backend/db/community` Diesel/PG.
HTTP 쓰기는 기존 Origin·본문 상한·세션 검증을 재사용한다. 댓글 작성/수정만 16 KiB, 삭제/신고는 8 KiB다.

동일 바이너리의 알림 채널에는 사이트 UUID만 보낸다. 공개 long-poll은 최대 20초·128개 연결이며 대기 중 PG 연결을 점유하지 않는다. 응답 전 공개 여부를 다시 확인하고 timeout 후에도 갱신하므로 다른 replica의 변경도 최종 반영된다. 브라우저 숨김 상태에서는 주기를 늦춘다. 페이지 전체 이동 없이 갱신하며 작성 중인 초안은 보존한다.

원 댓글 20개와 각 첫 답글 3개만 먼저 읽고, 전체 답글은 20개씩 읽는다. 기존 2,000자 초과 자료는 원본을 보존하고 화면에는 앞부분과 생략 안내를 표시한다. 실데이터에 그런 행이 있는지는 아직 확인하지 않았다.

Migration 010은 조회 인덱스와 신고 증거 보조 테이블을 추가한다. 원래 댓글·신고 ID/관계는 바꾸지 않는다. importer의 대상/격리 검증에도 증거 테이블을 추가해, 이관 후 새 쓰기를 재실행으로 지우지 않도록 했다.

## 검토와 남은 일

- DB 미설정 미리보기에서는 가상 댓글을 명시하고 저장을 막는다. 회원 UI 검증은 `member-browser-fixture.ps1 -IncludeSite -IncludeCommunity`의 가상 자료만 사용한다.
- 2026-09-14 미리보기 회귀: 예약 `.example` 주소의 댓글·답글·권한 읽기를 실제 서버 주소
  검사보다 먼저 예시 분기에서 처리한다. 알려진 예시 서버만 댓글을 제공하며 임의의 주소에
  스레드를 만들지 않는다. DB 설정이 있으면 기존 검증/권한을 유지하고, 쓰기에는 예외가 없다.
- 관리자 역할을 내부 회원 UUID에 명시적으로 부여하며 신고 목록/판정/삭제 표시/ban UI를 연결했다. 실제 운영 관리자 지정과 전체 관리자 기능 parity는 별도 남아 있다.
- 원문·신고 증거 보관 기간, 열람 권한/감사 기록, 장기 페이징/도배 규모는 운영 전 검토가 필요하다. 보관 기간을 임의 확정하지 않았다.
- 브라우저/PG 검증은 원격 AP 성공이나 실회원 이관 검증을 대체하지 않는다.
