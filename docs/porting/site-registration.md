# 회원의 신규 서버 등록

2026-09-14. `/servers`의 ‘목록에 없는 서버 등록’과 `/account/sites`에서
`/account/sites/new`로 연결한다. 기존 회원 화면의 폼·버튼·오류 표시를 공유한다.

## 원본과 새 흐름

MIT Phoenix `server_list_live.ex`의 `fetch_server` → NodeInfo 미리보기 →
`submit_server` → `Servers.create_server/1` 흐름을 기준으로 한다. 원본 UI는 복사하지 않았다.

1. 로그인한 회원이 도메인 또는 사이트 루트 주소를 입력한다.
2. 기존 수집 모듈로 HTTPS 응답과 NodeInfo를 확인한다. 아직 DB에 등록하지 않는다.
3. 이름·주소·소프트웨어·계정 수·가입 접수 상태를 미리 보여준다. 알 수 없음과 0/닫힘은 다르다.
4. 회원이 등록을 누르면 해당 도메인을 **다시 조회**한다. 브라우저가 보내는 미리보기 내용은 저장하지 않는다.
5. 현재 회원 권한을 다시 검사한 뒤 서버·최신 관측·비공개 등록 기록·첫 수집 작업을 한 트랜잭션으로 저장한다.
6. 서버 상세 또는 별도 운영자 인증으로 이어진다. 등록만으로 운영자 권한을 얻지 않는다.

NodeInfo 자체는 소유권 인증 수단이 아니며, 한국어 서버 여부를 자동 인증한 것도 아니다.
이 단계에서는 이름·소개를 운영자 편집값에 복사하지 않고 수집 관측값으로 둔다.

## 권한과 미확정 정책

이전 요구의 ‘서버 등록은 6개월 이상 된 계정’을 회원가입/로그인과 분리했다.
현재 초안은 **연결된 연합 계정 중 서버가 확인한 생성일이 180일 이상인 계정**을 사용한다.
생성일이 없거나 확인되지 않았거나 계정 연결이 해제되면 자격 근거로 쓰지 않는다.
자체 ID로 로그인했어도 해당 연합 계정이 연결되어 있으면 가능하다. 비공개 연동도 인정한다.

6개월 조건을 지금 적용할지 보류할지는 사용자에게 별도로 확인 요청한 상태다.
이 초안을 최종 정책 승인으로 간주하지 않는다. 기준은 `site_registration` 도메인 모듈의
별도 상수이며 로그인/소프트웨어 편집의 가입 조건을 변경하지 않는다.

운영 보호를 위한 현재 상한은 회원당 하루 신규 10개, 확인 요청은 회원당 15분 20회 및
전체 15분 120회다. 확인/확정 모두 요청 횟수에 포함한다. 동시 등록의 일일 제한은 회원 잠금으로 직렬화한다.

## 보존·보안 경계

- 미리보기/확정은 둘 다 인증·Origin·본문 8 KiB 제한을 적용하는 POST다. SSR/API 응답은 private/no-store다.
- 실제 HTTPS 조회 전에 현재 권한과 중복을 검사한다. DNS/IP 검증·연결 주소 고정·리디렉션 검사는 수집 모듈과 공유한다.
- 글/프로필 경로·포트·userinfo·내부 주소·제어 문자는 거절한다. URL 루트의 대소문자/IDN은 정규화한다.
- 루트 응답과 지원 NodeInfo/소프트웨어 정보를 확인하지 못하면 등록하지 않는다. 전체 조회는 30초, 각 HTTP 요청은 10초/본문 상한이 있다.
- 원격 IO 중에는 PG 연결이나 트랜잭션을 붙잡지 않는다. 조회 뒤 ban·세션 폐기·연동 해제·등록 제한을 재검사한다.
- 같은 도메인의 동시 등록은 UNIQUE 제약으로 하나만 성공한다. 중복은 원래 이름/소유권/숨김/강제 숨김/종료 상태를 변경하지 않는다.
- 수집 결과 저장은 워커와 같은 함수다. 첫 작업도 같은 PG 큐를 쓰므로 새 컨테이너/타이머/메시지 브로커가 없다.
- 등록자 ID는 공개 DTO에 없다. 탈퇴하면 귀속만 제거하고 다른 사람이 이용하는 서버 정보는 보존한다.
- `012`는 등록 기록, `013`은 요청 제한 scope를 추가하는 내장 migration이다. 이관 검증도 새 기록을 감지해 재이관으로 초기화하지 않는다.

## 검증과 남은 범위

- 실제 격리 PG + 실제 AP/수집 검증기에 합성 문서를 공급해 등록·관측·작업·소유권 분리,
  중복/숨김/동시 요청, 생성일, ban·세션 회수, 실패 시 미등록, 일일 제한·탈퇴를 검사한다.
- 브라우저 스크립트는 실제 HTTP에서 익명/Origin/본문/내부 주소/중복 거절과 private SSR을 확인한다.
  미리보기 성공과 등록 완료 화면만 명시적인 브라우저 모의 응답으로 검사한다. 이것을 실제 원격 등록 성공으로 세지 않는다.
- 별도의 수동 `check-live-site-preview.ps1 -Domain mastodon.social -AllowPublicNetworkRead`
  (또는 `misskey.io`)는 공유 `PublicHttp`로 실제 공개 루트/NodeInfo를 조회한다.
  최종 release에서 두 대상의 미리보기 200·제품 식별·통계/가입 상태 필드 존재를 확인했다.
  합성 로컬 회원만 사용하며 create 호출/사이트 등록/원격 게시/signed AP 인증은 하지 않는다.
  명시적 네트워크 옵션이 없으면 fixture 생성 전에 거부한다. 원격 상세·토큰은 출력하지 않는다.
- 실제 운영 서버를 대상으로 한 등록/수집 호환, 미확정 생성일 정책, 한국어 관련 안내,
  관리자 강제 조치와 불법·악성 등록 처리까지 완료됐다는 뜻은 아니다.
- 실행 결과는 [integration-checks.md](integration-checks.md), 전체 남은 작업은
  [교체 준비 현황](../cutover-readiness.md)을 기준으로 한다.
