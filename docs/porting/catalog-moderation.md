# 소프트웨어 관리자·종류 관리

2026-09-14. Phoenix의 MIT `software_info.ex`, `software_category.ex`,
`servers.ex`, `admin_live.ex`를 확인하고 기존 카탈로그 필드를 유지했다.
운영 자료가 아니라 가상 회원·제품·분류를 사용했다.

## 연결한 경로

- `/account/moderation/catalog`: 제품 검색, 잠금 필터, 24개 단위 목록.
- `/account/moderation/catalog/software/:name`: 회원 편집 잠금, 브랜드 색상,
  대표 제품 표식, 표시 순서의 개별 변경과 비공개 사유/이력.
- 같은 경로의 `/edit`: **기존 회원 EditorPage/EditForm을 재사용**한다.
  관리자 권한 확인 후 잠금 중에도 본문을 수정한다. 잠금은 해제하지 않는다.
  본문과 200자 변경 요약은 공개 이력이며, 관리 사유와 혼동하지 않게 안내한다.
- `/account/moderation/catalog/categories`: 종류 검색·24개 단위 목록.
- `/account/moderation/catalog/categories/new`: 종류 추가.
- `/account/moderation/catalog/category/:name`: 종류 표시 이름·이모지·순서 수정,
  동시 수정 비교와 비공개 이력. 등록 뒤 상세 주소로 이동한다.

일반 회원의 제품 등록/직접 편집/복원은 그대로다. 승인 대기함을 만들지 않았다.
분류 식별자는 변경·삭제하지 않아 기존 `categories` 배열과 `category_tag` 연결을
유지한다. 새 종류는 기존 공개 카탈로그와 회원 편집의 종류 선택에 반영된다.
분류 자체의 관리는 현재 관리자 기능이며, 일반 회원에게 분류 변경 권한까지
확대했다는 의미는 아니다.

표시 순서는 공개 목록에 적용된다. 브랜드 색상·대표 표식은 옛 메타데이터를
관리/보존하지만 현재 공개 화면에서 별도 강조로 사용하지 않는다. UI에도 이를
표시한다. 서버 추천 로직은 추가하지 않았다. 로고는 같은 화면의
[업로드·교체·삭제](catalog-logos.md)에 연결했다.

## 저장·권한·이력

- 같은 관리자 역할/세션을 매번 DB에서 재확인한다. 쓰기는 최근 15분 인증 필요.
  일반 회원·권한 회수·차단·폐기된 세션은 거절한다. 관리자임을 클라이언트가
  지정하는 플래그는 API에 없다.
- 잠금/메타데이터와 본문은 **같은 소프트웨어 revision**을 공유한다. 잠금 후
  해제해도 예전 폼은 409다. 회원 복원은 잠금 중 423이며 메타데이터를 복원하지 않는다.
- 조치는 선택한 필드만 변경한다. 기존 소개·분류·로고·수정하지 않은 값은 유지한다.
  기존 값이 새로운 입력 규칙을 벗어나더라도 다른 필드를 바꿀 때 강제 정규화하지 않는다.
- 첫 변경 전 전체 소프트웨어 snapshot을 baseline 0으로 남긴다. 설정 변경도
  공개 이력에는 설정 이름만 남기고, 사유·원래 타입의 전후 값은 별도 private 이력이다.
- 분류는 별도 revision이며, 최초 값과 변경 후 snapshot을 private 이력에 보존한다.
  사유 1,000자/4,000바이트, 이력 20개 단위. UI는 내부 JSON 대신 이름·아이콘·순서를
  표시한다. 긴 값은 표시 제한을 알리고 원본은 저장한다.
- no-op은 버전/이력을 늘리지 않는다. 같은 버전의 동시 쓰기는 하나만 성공한다.
  충돌 시 입력/사유를 보존하고 최신 내용을 명시적으로 확인한 뒤 다시 저장한다.
- 잠금 순서는 관리자 gate → 현재 회원/세션 → 제품/분류 → revision이다.
  DB 밖의 네트워크 작업은 없다. 분류 ID는 기존 bigint를 보존하며 짧은 별도 PG
  advisory lock 안에서 새 ID를 할당한다.
- 색상은 빈 값 또는 `#RRGGBB`만 받는다. CSS/URL을 입력값으로 실행하지 않는다.
  분류 이름은 200자, 아이콘 32자. 종류 식별자는 등록 시 소문자 정규화하고 중복 거절.
- API/SSR은 private/no-store. 공통 Origin/본문 제한 적용. 본문 수정만 64KiB,
  설정·분류 변경은 8KiB다. 로고 POST만 700,000바이트 전송 상한을 사용한다.
  DB/실제 인증이 없는 모드에서 관리자 저장을 흉내 내지 않는다.

## 이관·탈퇴

내장 migration 016은 `catalog_category_state`, `catalog_admin_events`를 추가하고
기존 제품 편집 이력의 action 제약을 확장한다. 기존 카탈로그 필드는 재작성하지 않는다.
관리자 탈퇴 시 private actor FK만 분리하고 이력은 남긴다. 이력이 존재하는 migration
되돌리기는 거절한다. importer의 빈 대상/재대조 검사에도 새 테이블을 포함하여
재이관으로 관리 상태나 이력을 초기화하지 않는다.

## 검증과 남은 범위

실행 기록은 [integration-checks.md](integration-checks.md)를 따른다.
전체 격리 PG, 실제 로컬 HTTP/브라우저, CLI 권한 회수 검사를 구분해 기록한다.

남은 것: 공개 이력에 잘못 게시된 개인정보의 제한 열람 처리, 분류 삭제/병합 정책,
일반 회원의 분류 자체 편집 정책, 편집 폼의 대량 종류 선택지. 공개 카탈로그 전체 검색/페이지,
오프라인 파일 보존과 로고 업로드는 후속으로 연결했다. 실제 ZIP/운영 DB 검증과
운영 활성화는 완료 범위가 아니다.
